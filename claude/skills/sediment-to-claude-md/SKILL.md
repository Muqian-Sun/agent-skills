# 把经验沉淀进全局 CLAUDE.md

全局 `~/.claude/CLAUDE.md` 每个会话都会加载，写进去的东西影响所有项目。所以要做对两件事：**只放真正跨项目通用的**，**放对位置**。否则它会越长越乱，该生效的规则被淹没；只跟某门语言有关的内容，还会在每个会话里白白占上下文。

`~/.claude/CLAUDE.md` 和 `~/.claude/refs` 都是软链，指向仓库 `Muqian-Sun/agent-skills` 的本地克隆 `~/Downloads/agent-skills/claude/` 下的同名文件和目录。改它们就是改这个仓库，改完按 `git-workflow` 提交并推送 main。

## 什么时候沉淀

在一个项目里沉淀出经验之后，把其中**通用、可复用**的部分写回全局 CLAUDE.md。写之前先过三道筛子：

- **换个项目也成立吗？** 只在这个项目里成立的约定，写进该仓库自己的 `CLAUDE.md` / `AGENTS.md`，不进全局
- **还会再遇到吗？** 一次性的修复、偶发的环境问题，不沉淀
- **已经有了吗？** 先把全局 CLAUDE.md 和它引用的文档读一遍。已有同类条目就合并或改写那一条，不另起一条说同一件事

## 放到哪里：按三类归位

| 经验属于 | 放在哪 | 怎么被读到 |
|---|---|---|
| **通用的**工作范式、踩过的坑、得出的经验 | CLAUDE.md 里开一个 `##` 子标签（已有合适的就加进去），子标签下分点写 | 每个会话常驻加载 |
| **特定语言的**坑和范式 | 用语言做标签，单独存成 `~/.claude/refs/<语言>.md`（已有就追加）；CLAUDE.md「引用的文档」里留一行引用，写明触发条件 | 只有碰到这门语言时才去读 |
| **特定的工作流程**（某一类任务从头到尾怎么做） | 写成一个 skill：`~/Downloads/agent-skills/claude/skills/<name>/SKILL.md`，description 写清触发场景；CLAUDE.md 里**不加引用** | skill 的 description 自动出现在可用列表里，命中场景时加载 |

分类拿不准时这样判断：**不分场景**都该遵守的，是通用的；**只在写某门语言时**才用得上的，是特定语言的；描述的是**某一类任务完整怎么做**的，是工作流程。

**「在写某门语言时踩到的」不等于「这门语言专有的」。** 判据是：换一门语言还会不会遇到？会遇到，就不归那门语言。和 shell、操作系统、命令行工具、写文件工具有关的坑，归进 `~/.claude/refs/shell.md`——不要因为是写 Go 时发现的就塞进 `go.md`，那样只有写 Go 时才读得到，换成写 Python 照样会再踩一次。

## 怎么写

- 分点写，一点只讲一件事
- 写清楚**为什么**，不只写规则本身——知道原因，才能在没见过的场景里判断这条适不适用
- 写成能照着做的判据，不写"注意 xxx"这种没法执行的提醒
- 特定语言文档的引用行，照 CLAUDE.md 里已有的格式写：路径 — 一句话说明。**触发：……时。**

## 改之前先给用户看

全局 CLAUDE.md 影响所有项目。把拟加或拟改的内容——归到哪一类、放在哪个位置、具体写什么——先给用户过目，确认后再写入。

新写的工作流程 skill，要装到 `~/.claude/skills/` 下才会被加载（软链到仓库里的目录即可），并且新开会话才生效。

## 反面模式

- ❌ 把项目专有的约定写进全局 CLAUDE.md
- ❌ 只和某门语言有关的内容直接堆进 CLAUDE.md 正文
- ❌ 在写某门语言时踩到的环境坑（shell、操作系统、工具），归进了那门语言的文档
- ❌ 工作流程写成 refs 文档、再在 CLAUDE.md 里引用——那是 skill 的活：skill 的描述会自动出现在可用列表里，refs 引用却要靠模型自己想起来去读
- ❌ 不查重，同一条经验换个说法又加一遍
- ❌ 没给用户看就改全局 CLAUDE.md
- ❌ 改完 CLAUDE.md、refs 或 skill 不提交推送——仓库和本机会对不上

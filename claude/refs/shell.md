# Shell 与本机环境：踩过的坑与范式

触发条件：跑 shell 命令、写 shell 脚本、批量改写文件时。

标「实测」的是本机（macOS + zsh）跑出来的结果。这些坑和用哪门语言无关——最初是写 Go 时踩到的，换一门语言照样会遇到。

- **macOS 没有 `timeout` / `gtimeout`**（实测）。要限时就用被调用程序自带的超时参数，比如 `go test -timeout 60s`；会卡死的演示靠它超时退出，不要指望外部命令。
- **zsh 不按空格拆分未加引号的变量**。`P="./a ./b"; go test $P` 会把整串当成一个参数，报 setup failed。包列表一律用数组：`P=(./a ./b); go test "${P[@]}"`。踩过一次，整轮验证结果作废。
- **非交互 zsh 里 `jobs -p` 拿不到后台进程的 PID**（实测）。靠它 `kill` 什么都没杀掉，`wait` 永远卡住。后台进程一律 `cmd & pids+=($!)` 记下来。**不要用死循环制造 CPU 负载来"模拟繁忙"**：踩过一次，8 个死循环跑了 22 分钟没人收。
- **用 perl 批量改含中文的源码，要 `perl -CSD -Mutf8`**。只写 `-CSD` 时输入按字符解码、脚本里的中文却还是字节，一处都匹配不上，而且不报错（实测）。改完 `grep -c` 数一遍替换结果。
- **写文件的工具会把 `\uXXXX` 转义替换成对应的字符**（会话里踩到两次）。运行输出完全一样，测试抓不住，只有和原文件 grep 比对才发现。含转义的源码写完要**数一遍出现次数**，或者用 perl 按字节写。

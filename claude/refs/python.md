# Python：踩过的坑与范式

触发条件：读、写或改 Python 代码时。

- **字节码缓存会让负向验证失效**：pyc 的失效判据是「源文件 mtime（**精确到秒**）+ size」，**两者同时未变才会误用旧字节码**。实测：同秒 + 等长改动 → 改动完全不可见；同秒但长度变了、或跨秒 → 正常重编译。
  - 危险的正是负向验证的典型手法：`>` 改 `<`、`+` 改 `-` 这类**单字符替换恰好等长**，在同一秒内「写坏 → 跑测试 → 还原」就会把坏字节码留下，让后续测试红得莫名其妙。
  - 做法：注入前后都清 `__pycache__`。**判据：还原后跑一次全量测试必须全绿；不绿就说明有残留，本轮全部结论不可采信。**
- **`hash()` 不能用在任何需要复现的地方**：Python 对 str/bytes 的 `hash()` 按进程随机加盐（PYTHONHASHSEED）。拿它派生种子、分桶、生成 ID，换个进程结果就变，而这类代码**当次运行永远自洽**，不会有任何东西变红。用 `hashlib` 代替。测法：用几个不同的 PYTHONHASHSEED 起子进程比对输出。
- **子进程不继承测试框架的路径设置**：pytest 的 `pythonpath` 只作用于当前进程。子进程里 import 项目包要显式传 `PYTHONPATH`，或确认包已真正装进环境。
- **改动包目录结构后 editable 安装会失效**：src 布局下增删子包，import 报 `ModuleNotFoundError` 而代码看起来完全正常。重新 `uv sync` / `pip install -e .`。
- **库的大版本会移除方法，别凭记忆调 API**：如 numpy 2.x 移除了 `ndarray.ptp()`（`np.ptp()` 仍在）、mcp 2.x 把 `FastMCP` 更名 `MCPServer`。可疑时当场 `hasattr` / `inspect.signature` 验一下，别等运行时报错。
- **mock / patch 的目标必须是真实被读的那个绑定**。早绑定（`from x import f` 之后持有的引用）、函数体内的局部 import、被同名定义覆盖的属性——patch 上去都不报错，测试全绿但什么都没测。改动模块结构后，逐个确认打桩点还落在被读的绑定上。
- **`ast` 的 `col_offset` 是 UTF-8 字节偏移，不是字符偏移**：按偏移改写含中文等非 ASCII 字符的源码会错位。批量改写还要做作用域分析，局部变量遮蔽同名符号时不能改。

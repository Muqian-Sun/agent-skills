# 产出挖掘：从日常工作里提炼简历 bullet

做两件事：**平时攒素材**，**需要时写 bullet**。

素材要当时就攒：会话记录默认只保留 30 天（`cleanupPeriodDays`），过期会被自动删掉；就算还在，隔久了当时为什么这么取舍、坑是怎么排查出来的、实测数字是多少，也很难再还原。

## 什么算素材

按含金量从高到低：

1. **需求**——最先挖，也最要写准。有需求才有功能，没有需求撑着的 bullet 会让人怀疑是凑的。写清楚：谁、在什么场景下、遇到了什么问题、要达到什么效果。"开发了 xx 功能"不是需求。
2. **方案与取舍**——功能设计、技术选型、方案设计，重点是**取舍**和**边界情况**：有哪些候选、为什么选这个、放弃了什么、考虑了哪些边界 case。
3. **踩过的坑**——最能证明是真做过的。但**低级错误不算坑**。判据：要靠实测、排查、读源码才发现，有经验的人也可能踩的，才是坑；拼写错、漏参数、看一眼文档或报错就能避免的，是低级错误，不记。
4. **Bug 及其解决**——现象、怎么定位的、根因是什么、怎么修的、怎么验证确实修好了。
5. **优化**——必须有**优化前后的实测数字**，并写清测法。没实测过就写"未实测"，不许估。

## 数据从哪来

**会话记录**：需求和取舍主要从这里挖。用本技能目录下的脚本，按日期抽出用户说过的话，以及在选择题里拍板的决策：

```bash
python3 <本技能目录>/scripts/extract_sessions.py --since 2026-09-01 [--until 2026-09-16] [--cwd 关键字]
```

- 输出按项目目录、按会话分组，已经过滤掉工具结果、系统注入的内容和子 agent 的记录
- **退出码不是 0 时，先看 stderr**：有解析不了的记录或没见过的格式时，脚本仍会输出能解析的部分，但结果不全，不能当成全量
- 需要看某次排查的具体过程时，再按时间点回到原始 `.jsonl` 里翻

**git 提交**：对脚本输出里出现的每个项目目录：

```bash
git -C <目录> log --author="$(git -C <目录> config user.email)" --since=<日期> --stat
```

按作者筛时，每个仓库都要读它自己配置的 `user.email`——不同仓库可能配的不是同一个邮箱。

**两边对不上时以 git 为准**：会话里说过要做的，不一定真落地了。

## 攒素材

存在 `~/Documents/产出记录/YYYY-MM.md`。放在任何项目仓库之外，不进版本库。一件事记一条：

```markdown
### 2026-09-16 · claude-skills · 把新人导览拆成「系统地图 + 单仓深入」两个 skill

- **需求**：新人接手服务时往往只拿到一个仓库，默认仓库就是系统全貌，结果请求链路讲到一半断在别人的仓库里
- **方案与取舍**：拆成两个 skill；共享的三块内容复制两份并标注同源，而不是跨 skill 引用——模型不保证会去读另一个 skill
- **坑**：用 skill-creator 测触发率，recall 接近 0；查源码发现评测默认在家目录下跑，那里没有仓库可看，所以这个数字不可信
- **证据**：commit `366b55c`、`2b72b0e`；会话 a4060930，2026-09-11
```

某一项没有就不写，不要凑。**证据**一项必须有：commit、会话 ID 加日期、实测输出，至少一样。

## 写 bullet

- 先从素材库里挑，缺的再用上面的数据源补
- 每条 bullet 用一句话讲清：**在什么需求下 → 做了什么（含关键取舍）→ 结果**
- 结果能量化就量化，数字必须来自素材里的实测；没有数字就写定性结果，不编
- 同一个项目内按含金量排序：需求清晰、有取舍、有实测数字的排前面
- 每条 bullet 下面附一行证据，这行不进简历，是给用户核对用的

示例：

> 针对新人接手服务时只拿到单个仓库、看不清系统全貌的问题，设计「系统构成地图 + 单仓深入」两阶段导览：从本地代码、代码托管平台、线上环境三条线索交叉定位服务边界，并按「范围 / 聚焦」分层决定每个服务读到多深
>
> 证据：commit `366b55c`、`2b72b0e`

## 反面模式

- ❌ bullet 只写"负责 xx 模块开发""使用了 xx 技术"，没有需求，也没有取舍
- ❌ 把拼写错误、漏传参数这类低级错误当成坑写
- ❌ 优化写"性能大幅提升"，没有前后实测数字，或者数字是估的
- ❌ 写了会话里说过、但 git 里没有落地的事
- ❌ 素材某项没有也硬凑，或者一件事拆成好几条
- ❌ 把素材库写进项目仓库里
